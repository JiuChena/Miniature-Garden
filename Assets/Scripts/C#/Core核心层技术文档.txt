# Core 核心层技术文档

## 一、单位状态展示模块（BaseUnitStatus）

### 设计目标

每个单位只需挂载一个 StatusData（数据层已存在），展示层通过继承 BaseUnitStatus 来定制该单位需要显示哪些状态 UI。框架不内置任何具体显示（包括血条），全部通过 IStatusExtension 扩展机制按需组合。

### 核心接口

1. IStatusViewProvider — UI 视图创建/销毁
2. IStatusTickable — 每帧接收 StatusData 驱动 UI 更新

一个扩展按需组合接口，只实现自己需要的：

HealthBarExtension：实现 IStatusViewProvider + IStatusTickable，需要 UI + 数据更新
DamageNumberExtension：实现 IStatusViewProvider + IStatusTickable，需要 UI + 数据更新
DeathEventListener：只实现 IStatusTickable，不需要 UI，纯监听

### 框架层代码（Framework/Gameplay/Core/）

IStatusViewProvider.cs

public interface IStatusViewProvider
{
    void OnCreateView(Transform canvasParent);  // 在 Canvas 下创建 UI
    void OnDestroyView();                       // 销毁 UI
}

IStatusTickable.cs

public interface IStatusTickable
{
    void OnTick(StatusData data);  // 每帧读取 StatusData 更新 UI
}

BaseUnitStatus.cs

public abstract class BaseUnitStatus : MonoBehaviour
{
    // World-Space Canvas 根节点（自动创建）
    protected Transform CanvasRoot { get; private set; }

    // 子类实现：决定要哪些扩展
    protected abstract void RegisterExtensions();

    // 注册扩展，按接口自动分派
    protected void AddExtension(object ext)
    {
        if (ext is IStatusViewProvider viewProvider)
            viewProvider.OnCreateView(CanvasRoot);
        _extensions.Add(ext);
    }

    // Awake: 创建 Canvas → 调用 RegisterExtensions
    // LateUpdate: 遍历 _extensions，调用 IStatusTickable.OnTick
    // OnDestroy: 遍历 _extensions，调用 IStatusViewProvider.OnDestroyView
}

### 业务层代码（Business/MiniatureGarden/Character/）

// 角色状态 — 需要血条 + 跳字 + 暴击显示
public class CharacterStatus : BaseUnitStatus
{
    [SerializeField] private GameObject _healthBarPrefab;
    [SerializeField] private GameObject _damageNumberPrefab;

    protected override void RegisterExtensions()
    {
        AddExtension(new HealthBarExtension(_healthBarPrefab));
        AddExtension(new DamageNumberExtension(_damageNumberPrefab));
    }
}

// 敌人状态 — 只要血条
public class EnemyStatus : BaseUnitStatus
{
    [SerializeField] private GameObject _healthBarPrefab;

    protected override void RegisterExtensions()
    {
        AddExtension(new HealthBarExtension(_healthBarPrefab));
    }
}

// 场景机关 — 什么都不要
public class DestructibleObject : BaseUnitStatus
{
    protected override void RegisterExtensions() { }
}

### 预制体引用方式

不使用字符串路径（避免拼写错误），扩展通过构造函数接收预制体引用：

public class HealthBarExtension : IStatusViewProvider, IStatusTickable
{
    private readonly GameObject _prefab;  // 编译期安全，零字符串
    private Slider _slider;

    public HealthBarExtension(GameObject prefab) { _prefab = prefab; }

    public void OnCreateView(Transform canvasParent)
    {
        var viewRoot = Object.Instantiate(_prefab, canvasParent);
        _slider = viewRoot.GetComponent<Slider>();
    }

    public void OnTick(StatusData data)
    {
        _slider.value = data.CurrentHealth / data.MaxHealth;
    }

    public void OnDestroyView()
    {
        Object.Destroy(_slider.gameObject);
    }
}

## 二、DamageNumberPool 移除方案

### 现状

DamageNumberPool（237 行）在 Framework/CoreFramework 下，但它的具体行为（跳字颜色、缩放动画、伤害格式化）属于业务逻辑。

每个跳字是独立 GameObject + 独立 TMP_Text + 独立 MeshRenderer，每个跳字至少 1 DC。AOE 10 个敌人 × 5 个跳字 = 50 DC。

### 方案

跳字改为 DamageNumberExtension，挂载在 BaseUnitStatus 子类的扩展中。核心改变：

- 跳字不再使用独立 GameObject + TMP_Text（TextMeshPro），改用 Canvas 内的 TMP_UGUI（TextMeshProUGUI）
- 一个单位所有跳字在同一个 World-Space Canvas 内，天然合批
- 10 个敌人 → 10 个 Canvas → 10 DC（减少 80%）

### 迁移步骤

1. 创建 Framework 层：BaseUnitStatus + IStatusViewProvider + IStatusTickable
2. 创建 Business 层：DamageNumberExtension（从 DamageNumberPool 迁移核心逻辑）
3. 创建 Business 层：CharacterStatus / EnemyStatus（继承 BaseUnitStatus）
4. 把所有单位的组合改成挂 CharacterStatus
5. 删除 Framework/CoreFramework/DamageNumberPool 整个目录

## 三、框架层 vs 业务层边界

框架层（Framework）：
- BaseUnitStatus：World-Space Canvas 生命周期、Extension 注册/分派
- IStatusViewProvider / IStatusTickable：扩展接口契约
- 不内置任何具体显示（血条、跳字、Buff 图标全不是框架的事）

业务层（Business）：
- CharacterStatus / EnemyStatus 等：继承 BaseUnitStatus，决定扩展组合
- HealthBarExtension / DamageNumberExtension / BuffIconExtension 等：具体实现
- 预制体制作、颜色、动画、样式

核心原则：框架只提供壳（Canvas + 扩展分派），业务填内容（具体 Extension）。

## 四、架构决策记录

### ADR-007: 单位状态展示使用 World-Space Canvas + 扩展机制

- 决策：每个单位根节点下挂 BaseUnitStatus，内部创建 World-Space Canvas，通过 IStatusExtension 扩展机制组合显示
- 替代方案被拒绝：
  - 独立 GameObject + TMP_Text（当前 DamageNumberPool 方案）：DC 太多，不合批
  - GPU Instancing：绕过 TMP 生态自己管矩阵，开发量大
  - ComputeBuffer Shader：开发量最大，调试困难
- 后果：需要砍掉 DamageNumberPool，迁移为 DamageNumberExtension

### ADR-008: 预制体引用走构造函数，不走字符串路径

- 决策：扩展通过构造函数接收 GameObject prefab，BaseUnitStatus 子类通过 [SerializeField] 在 Inspector 拖入
- 替代方案被拒绝：
  - 字符串 Addressable Key：拼写错误无编译期检查
  - 接口内声明路径属性：仍然是字符串，同样问题
- 后果：零字符串路径，全部编译期检查
