# 2026-06-23

## 讨论
- [[modules/player-control]] — 同步最近的玩家输入与摄像机输入收束改动
- 重点校准 `Alt` / UI 禁用玩法输入的真实链路，避免知识库继续沿用旧的补丁式描述

## 决策
- 以后代码改动完成后，知识库同步视为默认收尾步骤，不再作为可选项单独确认
- 玩家玩法输入总开关统一收束在 `PlayerInputModule`
- `PlayerCameraController` 不再自己判断 Alt，只消费 `SetGameplayInputEnabled(bool)` 的结果
- 相机输入冻结同时覆盖 `CinemachinePOV` 与 `CinemachineInputProvider` 这两条实际镜头输入链

## 本次同步的事实
- `PlayerTransformSyncModule` 相关描述从玩家控制主链笔记中移除，当前由 `PlayerMovementModule` 负责 Player 根节点移动与角色对齐
- `CharacterTargetingModule` 的旧表述更新为 `UnitTargetingModule`
- 玩家交互范围汇总当前归 `PlayerInputModule` 作为 `ICharacterInteractionSource` 输出
- `Alt` 按住与 UI 打开都走同一个玩法输入总开关
- 输入禁用时终止的是“新的玩法输入进入 Blackboard”，不是强制打断已在执行中的行为

## 敌人 Driver 方案整理
- [[modules/enemy-ai]] 从“预留说明”升级为“正式实现方案”
- 明确敌人和角色共用同一套行为编辑器、`BehaviorClip`、`BehaviorInterpreter`、`HSM` 状态层
- 敌人与角色的主要分叉点被收束为：
  - 输入来源：玩家输入 vs AI 决策
  - 导航执行：PlayerMovement vs NavMeshAgent
  - 高层策略：CharacterTransitionPolicy vs EnemyTransitionPolicy
- 明确敌人也支持：
  - `LoadState`
  - 蹲下
  - 翻越障碍
- 明确后续实现时，凡是与角色系统高度相似且值得复用的模块，应优先上提到共通层，而不是复制一份敌人专用实现

### 运行态继续暴露出的两个真实问题
1. 行为事件骨骼路径兼容问题
   - 运行态会报：`未找到骨骼路径：CH0167`
   - 原因是共用行为资源里 `referenceBone` 还带着旧角色根节点名
   - 已在 `BehaviorInterpreter` 里补“旧根节点前缀自动剥离”的兼容解析
   - 再次进入 Play 后，这条 warning 已不再出现

2. 霰弹枪敌人替换 prefab 后丢失 `CharacterController`
   - 这会让它们虽然能在攻击距离里打，但 `Move / Vault` 的基础不完整
   - 根因有两层：
     - `Enemy_Solider_霰弹枪.prefab` 之前本体没有 `CharacterController`
     - 敌人工具菜单原本是靠 `CharacterController[]` 扫描候选对象，一旦对象把 `CharacterController` 丢了就会直接从工具视野消失
   - 已修正：
     - 给正式敌人 prefab 加入 `CharacterController`
     - `CollectSceneEnemyCandidates()` 改成同时扫描 `CharacterController` 和 `EnemyDriver`
     - `EnemyAuthoringUtility.ConfigureEnemyObject()` 先确保 `CharacterController`
     - `EnemyDriver` 增加 `[RequireComponent(typeof(CharacterController))]`
